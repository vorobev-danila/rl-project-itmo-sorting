# Подготовка и сдача практикума 3

Команда K02, направление `environments`, дорожка A. Подготовлено 52 случая из
реальных задач Sorting: 20 общих и 32 дополнительных. Каждый случай — один
исходный эпизод и один конкретный предложенный порядок. Включены задачи с 3–5
объектами, без единиц, с одной единицей и со смешанными приставками. Предлагаемые
порядки целенаправленно включают разные исходы; доли ошибок описывают этот срез,
а не распространённость ошибок в природе. Отбор воспроизводится с seed 2026.

## Что уже готово

- `audit/slice.jsonl` — данные без машинных меток и нормализованных ответов.
- `audit/instruction.md` — инструкция 1.0 с двумя метками CORRECT/INCORRECT.
- `audit/annotations.csv` — 112 назначений. Из личных пакетов A1–A3 сведены
  84 метки с записанным временем. Каждый из трёх участников разметил 20 объектов
  ядра и 8 объектов второго круга. Назначения A4 ожидают независимых меток и
  фактического времени. В отдельной локальной копии у A4 есть расчётный черновик.
- `audit/baseline_predictions.csv` — 52 вердикта numeric-only.
- `audit/probe_results.csv` — заголовок; численные результаты хранятся отдельно
  до завершения человеческой разметки.
- `annotation_packets/A1.md` … `A4.md` — удобное представление личных заданий.
- `annotation_packets/A1.csv` … `A4.csv` — личные таблицы по 28 суждений.
- В `notebooks/` есть выполненные копии A1 и A4 с настройками K02/environments.
  Для сдачи ещё нужны индивидуальные копии A2 и A3.

Папка `annotation_packets` вспомогательная: в итоговой форме обязательны папки
`audit` и `notebooks`. Разметчикам выдавайте только инструкцию и их личные пакеты.
Не запускайте заново генератор CSV из ноутбука после начала разметки: он
перезаписывает файлы. Все четыре участника пока указаны как разметчики; если один
будет только хранителем ответов, назначения нужно согласовать до начала работы.

## Реальные действия участников

1. Зафиксировать соответствие людей A1–A4. Начать с первых 10 общих объектов.
2. Независимо заполнить свои CSV: метку и фактическое время. Пройти все 20 общих
   объектов и 8 дополнительных (допустимый минимум — 4 дополнительных).
3. При уточнении инструкции хранить обе версии и корректно отмечать версию
   последующих суждений. Не менять уже сохранённые ответы ради совпадения.
4. Когда все закончат, ответственному собрать личные таблицы:

```text
python lab3_audit.py merge
```

Команда не должна подменять независимую разметку выводом программы. Пустые поля
в подготовленных файлах означают «ещё не размечено», а не ошибку подготовки.
Отдельная таблица `docs/manual_proxy_review.csv` из П2 остаётся самостоятельной
проверкой прокси; её 33 строки не заменяют разметку 52 случаев практикума 3.

## Машинный запуск для хранителя ответов

Эта часть выполняется только хранителем, который не размечает данные, или куратором.
Требуются Python 3.10+ для скрипта и Java 8 в PATH; метаданные существующего проекта
по-прежнему требуют Python 3.12+. Дополнительная зависимость указана в
`requirements-lab3.txt`. Исходные файлы библиотеки не модифицируются.

```text
python -m pip install -r requirements-lab3.txt
python lab3_audit.py score --private-dir <закрытая_папка_вне_репозитория>
```

Генератор сверяет исходные объекты с живой средой версии 1.1.0, перед каждым
случаем делает reset и останавливается на первом done=True. Успех — score==1.0;
неудача должна быть подтверждена taskfailure. Недопустимая команда, расхождение
исходных объектов, таймаут и отсутствие штатного завершения прерывают запуск,
а не превращаются в неправильный ответ оценщика. Gold path не используется.

В закрытой папке сохраняются `scorer.jsonl`, заполненный `probe_results.csv`,
пошаговые `traces.csv` и отпечаток входного среза в `provenance.json`.
Папка должна иметь доступ только у хранителя/куратора; одно лишь расположение
вне Git не является ограничением доступа. Не коммитьте машинные ответы даже
во временную ветку: история Git сохраняет удалённые впоследствии ответы.

Подготовлены три зонда: ложное принятие неверного порядка, ложное отклонение
правильного порядка и расхождения numeric-only с прокси на смешанных единицах.
Их численные результаты относятся к независимому автоматическому прокси,
а не к завершённой человеческой разметке. Ручная проверка прокси остаётся нужна.

Только после завершения всей человеческой разметки хранитель раскрывает ответы:

```text
python lab3_audit.py release --private-dir <та_же_закрытая_папка>
```

Команда проверяет полноту общего ядра, минимум 24 суждения на каждого участника,
метки, время и совпадение SHA-256 среза; затем копирует в `audit/` только два
обязательных файла. Пошаговые следы не нужны для сдачи и остаются у хранителя.
Проверка заполненности не доказывает, что люди действительно работали независимо.

## Итоговый комплект

В `audit/` должны находиться slice.jsonl, instruction.md, annotations.csv,
baseline_predictions.csv, probe_results.csv и scorer.jsonl. В `notebooks/`
каждый участник сохраняет свой выполненный блокнот с результатами запуска.
Команда отправляет одну Google Form со ссылкой на общую папку GitHub.
Пока люди не заполнили таблицы, комплект подготовлен к работе, но не к итоговой сдаче.
В локальной рабочей копии проверены 52 вердикта оценщика и три зонда для текущего
среза. Их добавляют в Git после завершения независимой человеческой разметки.
Файл `audit/scorer.jsonl` до этого исключён через `.gitignore`; при итоговой
публикации после окончания разметки его нужно добавить явно: `git add -f audit/scorer.jsonl`.

Скрипт `prepare` нужен только для воспроизведения подготовки в чистой копии:
он намеренно отказывается перезаписывать уже существующие таблицы. Версии файлов
и формат назначений согласованы с генератором из выданного студенческого блокнота.

Источники: [TextWorldExpress 1.1.0](https://pypi.org/project/textworld-express/1.1.0/),
[официальный Python API](https://github.com/cognitiveailab/TextWorldExpress/blob/main/textworld_express/textworld_express.py).
