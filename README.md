## Исследовательский вопрос

В каких случаях принятие или отклонение порядка объектов штатным оценщиком среды **TextWorldExpress Sorting** на тестовых эпизодах `sorting` расходится с независимым прокси-эталоном правильной сортировки величин по возрастанию после приведения совместимых единиц к общей базовой единице?

Отдельно проверяем случаи с 3, 4 и 5 объектами, а также эпизоды без единиц, с одной единицей и со смешанными приставками единиц.

## Данные и срез

**Набор данных:** процедурно сгенерированные эпизоды среды [TextWorldExpress](https://github.com/cognitiveailab/TextWorldExpress), версия `textworld-express==1.1.0`.

**Конфигурация, срез и правило отбора:** `gameName="sorting"`, стандартные параметры среды, `gameFold="test"`, `seed=0..99`, `envStepLimit=20`, `generateGoldPath=False`. Для каждого из 100 seed сохраняем начальное наблюдение и список объектов. Для каждого эпизода запускаем все перестановки объектов (при 3–5 объектах это 6–120 вариантов порядка); для каждой перестановки сохраняем задуманный полный порядок, фактически исполненные действия, пошаговые `reward`, `done` и `score`, а также итоговый `score`. Предварительный обход дерева состояний не используем.

Результаты группируем по числу объектов (3, 4, 5), виду единиц (без единиц; одна и та же единица у всех объектов; смешанные приставки одной физической размерности), а также по пересечениям этих признаков. Если какая-либо группа не встретилась, фиксируем `N=0`, а не заменяем seed.

Среда требует Java 1.8. В `sorting` нужно по одному помещать 3–5 объектов в ящик по возрастанию величины. В версии 1.1.0 неверное размещение приводит к `score == -1.0`, `taskfailure=True` и `done=True`; это поведение соответствует [исходному оценщику Sorting](https://github.com/cognitiveailab/TextWorldExpress/blob/main/simulator/src/main/scala/textworldexpress/games/SortingGame.scala#L35-L58). Настраиваемых параметров сложности у этого среза нет.

## Эталон и метод

**Эталонный исход или прокси:** отдельная Python-функция разбирает число и единицу каждого объекта, приводит значения одной физической размерности к общей базовой единице и проверяет неубывающий порядок. Перестановка считается правильной тогда и только тогда, когда каждое следующее нормализованное значение не меньше предыдущего. Прокси реализуется независимо от исходного кода оценщика и не использует `reward`, `done` или `getGoldActionSequence()`.

Прокси проверяет только математическую правильность порядка. Он не покрывает качество естественно-языковых формулировок, допустимые синонимы команд, удобство интерфейса, эффективность агента и физические единицы, которых нет в генераторе.

**Протокол исполнения перестановки:**

1. Перед каждой перестановкой сбрасываем среду с теми же `seed`, `gameFold="test"` и настройками, включая `generateGoldPath=False`.
2. Для каждого объекта в заданном порядке выполняем `take <объект>`, затем `put <объект> in box`; перед действием проверяем его наличие в текущем списке `validActions`.
3. После каждого действия записываем результат и немедленно останавливаем исполнение при первом `done=True`, в том числе между `take` и `put`. После этого не вызываем `step` до сброса среды для следующей перестановки. Среда позволяет продолжать действия после `done=True` и затем получить `score == 1.0`, поэтому продолжение исказило бы оценку.
4. Математическую правильность проверяем для задуманной полной перестановки, даже если среда отклонила её до исполнения всех действий.

**Оцениваемый оценщик:** штатное решение среды TextWorldExpress о принятии или отклонении порядка. При штатном завершении порядок считается принятым, если на первом `done=True` получен `score == 1.0`; в остальных случаях штатного завершения он считается отклонённым. Сигналы `reward` и `done` сохраняем в протоколе для разбора, но корректность каждой промежуточной награды и момента завершения отдельно не оцениваем.

Ошибки парсинга, недопустимые команды, сбои среды и исчерпание лимита без штатного успеха или неудачи задачи фиксируем отдельно как ошибки прокси или протокола, а не как `FP`/`FN`. Устраняем их и повторяем затронутые прогоны; до этого итоговый критерий не считается проверенным. Такие случаи нельзя молча исключать из выбранного набора или заменять другими seed.

**Базовое сравнение:** простой `numeric-only`-оценщик, который сортирует только по записанному числу и игнорирует единицы и их масштаб. Сравнение покажет, даёт ли приведение единиц преимущество именно на эпизодах со смешанными приставками.

## Метрика и критерий

**Метрика ошибки:** доля расхождений

```text
disagreement_rate = (FP + FN) / N
```

где `FP` — число перестановок, которые среда приняла (`score == 1.0` на первом `done=True`), а прокси признал неправильными; `FN` — число перестановок, которые среда отклонила, а прокси признал правильными; `TP` — число математически правильных перестановок, принятых средой; `N` — общее число перестановок, исполненных по протоколу во всех выбранных эпизодах, включая отклонённые до конца последовательности действий. В отчёте выражение вычисляется как `(FP + FN) / N`; отдельно приводятся `FP / N`, `FN / N`, доля ложных отклонений среди правильных порядков `FN / (TP + FN)`, абсолютные количества и результаты по каждому срезу.

При `N=0` указываем `N/A` для долей с этим знаменателем, сохраняя `N=0` и абсолютные количества. При `TP + FN == 0` указываем `N/A` для доли ложных отклонений. Отсутствие данных не трактуем как нулевую ошибку или подтверждение качества на этом срезе.

**Численный критерий успеха:** после обработки всех перестановок не менее чем 100 уникальных тестовых эпизодов без неустранённых ошибок прокси или протокола одновременно должны выполняться условия:

- общая доля расхождений `(FP + FN) / N` — не более **1%**;
- общее число ложных принятий `FP` — **0**;
- доля ложных отклонений `FN / (TP + FN)` — не более **1%** в целом и в каждом срезе с ненулевым знаменателем: по числу объектов, виду единиц и их пересечениям.

Контроль `FN / (TP + FN)` не позволяет скрыть отклонение правильных порядков за большим числом неверных перестановок. Порог 1% относится к расхождениям с проверенным прокси, а не к допустимым ошибкам его парсинга. Нулевой порог по `FP` не позволяет среде выдавать максимальную награду за математически неверный порядок. Отсутствующие срезы отмечаем отдельно и не распространяем на них вывод.

## Риск и границы

**Возможная ошибка оценщика:** среда может выдать `score == 1.0` для неверного порядка из-за неправильного преобразования приставок (`mg`, `g`, `kg` и аналогичных единиц), сравнения строк вместо нормализованных чисел, ошибки округления или неверного правила для равных значений. Возможна и обратная ошибка: правильный порядок будет отклонён.

**За границами проекта:** обучение и сравнение RL-агентов; остальные семь сред TextWorldExpress; train/dev-срезы; проверка корректности всех промежуточных наград и момента завершения; производительность симулятора; полный обход карты или дерева состояний; оценка языкового разнообразия; добавление новых объектов и единиц; доказательство корректности всей библиотеки.
