## Исследовательский вопрос

В каких случаях встроенный оценщик `reward`/`done` среды **TextWorldExpress Sorting** на тестовых эпизодах `sorting` расходится с независимым прокси-эталоном правильной сортировки величин по возрастанию после приведения совместимых единиц к общей базовой единице?

Отдельно проверяем случаи с 3, 4 и 5 объектами, а также эпизоды без единиц, с одной единицей и со смешанными приставками единиц.

## Данные и срез

**Набор данных:** процедурно сгенерированные эпизоды среды [TextWorldExpress](https://github.com/cognitiveailab/TextWorldExpress), версия `textworld-express==1.1.0`.

**Конфигурация, срез и правило отбора:** `gameName="sorting"`, стандартные параметры среды, `gameFold="test"`, `seed=0..99`, `envStepLimit=20`, `generateGoldPath=False`. Для каждого из 100 seed сохраняем начальное наблюдение, список объектов, действия, `reward`, `done` и итоговый `score`. Для каждого эпизода запускаем все перестановки объектов (при 3–5 объектах это 6–120 вариантов порядка). Результаты дополнительно группируем по числу объектов и виду единиц; если какая-либо группа не встретилась, фиксируем `N=0`, а не заменяем seed. Предварительный обход дерева состояний не используем.

Среда требует Java 1.8. Согласно документации, в `sorting` нужно по одному помещать 3–5 объектов в ящик по возрастанию величины; ошибка обнуляет результат и завершает игру. Настраиваемых параметров сложности у этого среза нет.

## Эталон и метод

**Эталонный исход или прокси:** отдельная Python-функция разбирает число и единицу каждого объекта, приводит значения одной физической размерности к общей базовой единице и проверяет неубывающий порядок. Перестановка считается правильной тогда и только тогда, когда каждое следующее нормализованное значение не меньше предыдущего. Прокси реализуется независимо от исходного кода оценщика и не использует `reward`, `done` или `getGoldActionSequence()`.

Прокси проверяет только математическую правильность порядка. Он не покрывает качество естественно-языковых формулировок, допустимые синонимы команд, удобство интерфейса, эффективность агента и физические единицы, которых нет в генераторе.

**Оцениваемый оценщик:** штатный сигнал среды TextWorldExpress — итоговая пара `score/reward` и `done`. Порядок считается принятым оценщиком, если эпизод завершился с итоговым `score == 1.0`; во всех остальных случаях он считается отклонённым.

**Базовое сравнение:** простой `numeric-only`-оценщик, который сортирует только по записанному числу и игнорирует единицы и их масштаб. Сравнение покажет, даёт ли приведение единиц преимущество именно на эпизодах со смешанными приставками.

## Метрика и критерий

**Метрика ошибки:** доля расхождений

```text
disagreement_rate = (FP + FN) / N
```

где `FP` — число перестановок, которые среда приняла (`score == 1.0`), а прокси признал неправильными; `FN` — число перестановок, которые среда отклонила, а прокси признал правильными; `N` — общее число исполненных перестановок во всех выбранных эпизодах. В отчёте выражение вычисляется как `(FP + FN) / N`; отдельно приводятся `FP / N`, `FN / N`, абсолютные количества и результаты по каждому срезу.

**Численный критерий успеха:** на не менее чем 100 уникальных тестовых эпизодах общая доля расхождений должна быть не более **1%**, при этом ложных принятий должно быть **0**. Порог 1% допускает единичные проблемы парсинга прокси для последующего ручного разбора, а нулевой порог по `FP` не позволяет среде выдавать максимальную награду за математически неверный порядок.

## Риск и границы

**Возможная ошибка оценщика:** среда может выдать `score == 1.0` для неверного порядка из-за неправильного преобразования приставок (`mg`, `g`, `kg` и аналогичных единиц), сравнения строк вместо нормализованных чисел, ошибки округления или неверного правила для равных значений. Возможна и обратная ошибка: правильный порядок будет отклонён.

**За границами проекта:** обучение и сравнение RL-агентов; остальные семь сред TextWorldExpress; train/dev-срезы; производительность симулятора; полный обход карты или дерева состояний; оценка языкового разнообразия; добавление новых объектов и единиц; доказательство корректности всей библиотеки.
